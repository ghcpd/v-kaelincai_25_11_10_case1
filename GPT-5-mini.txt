How the enhanced feature works (implementation notes)
•	Storage: uses browser localStorage key search_history_v1.
•	Display: shows up to DISPLAY=5 items (most-recent-first). Full stored history capped at MAX_ITEMS=100.
•	Deduplication: new or repeated search moves item to front and removes duplicate older copies.
•	Keyboard support: ArrowDown/ArrowUp sets highlight (aria-selected), Enter selects highlighted item, Escape closes dropdown.
•	Privacy controls: "Clear History" button removes stored entries; "Disable persistence" checkbox turns off future writes and removes existing persisted key.
•	Accessibility: role="listbox"/role="option", aria-expanded, aria-hidden, aria-live on results. Focus management keeps input focused; mousedown is used on items for click reliability.

Pitfalls, failure modes and limitations (important)
•	Race conditions: concurrent writes to localStorage from parallel tabs could create ordering anomalies. Recommended mitigation: use short critical sections or switch to server-side history with optimistic locking for heavy concurrency.
•	Injection/malicious history items: stored strings may contain control chars; UI renders them as text but you should sanitize or escape when rendering into HTML in a real product and limit stored length.
•	Storage quota: localStorage is limited per-origin (typically several megabytes); test harness stores small strings but production must handle storage full errors (our code catches JSON errors and fails gracefully).
•	Headless vs real-device differences: headless browser timing and focus behavior may differ from real browsers. The harness is best-effort for automated verification; real-world can differ due to input method editors, screen readers, or mobile touch events.
•	Playwright dependencies: Playwright requires browser binaries; on Windows additional dependencies may be needed. See Playwright docs if you hit issues.
•	Scripts assume a Bash orchestration environment for run_all.sh — PowerShell alternatives are provided, but run_all.sh is easiest in Git Bash/WSL.
Security & privacy notes
•	The demo uses localStorage which persists data on the client; ensure compliance with privacy policy and allow users to opt-out (checkbox implemented).
•	For production, consider server-side opt-in encrypted storage if search terms are sensitive.
•	Provide UI explanations when persistence is on and provide an accessible way to clear history.
